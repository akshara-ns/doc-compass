A1. Red-flag rules: four gaps and one negation bug                  doccompass/redflags.py
------------------------------------------------------------------------------------------
Problem
  Missed:          "my chest hurts really badly"         (most common way to say it)
                   "I can barely breathe"
                   "thoughts of ending it all"
                   "worst headache ever, came on suddenly"
  Wrongly flagged: "I don't want to die from this, should I see a dermatologist"
                   -> shows the emergency banner and the 988 crisis line.
                   Cause: the negation list has "didn't" and "don't have" but not plain
                   "don't" / "doesn't".

Fix (tested: these 4 now flag, the false alarm is gone, all existing test phrases still
behave the same)

  1. chest pain rule, add to the end of the pattern:
       |\bchest (?:hurts|is hurting|feels tight|feels heavy)\b

  2. breathing rule, add "can barely" and "barely able to" to the opening group:
       \b(?:{_CANT}|can barely|barely able to|struggling to|hard to|trouble|difficulty) breath(?:e|ing)\b

  3. suicidal thoughts rule, add to the end of the pattern:
       |\bend(?:ing)? it all\b|\btake my (?:own )?life\b

  4. sudden severe pain rule, change the last alternative to:
       |\bworst (?:headache|pain) (?:of my life|ever)\b

  5. _NEGATION, replace the word list with:
       (?:no|not|never|without|denies|deny|didn'?t|don'?t|doesn'?t|haven'?t|isn'?t|wasn'?t)
     ("I don't want to live" is still flagged: that match starts at "don't", so the
     negation check never sees it.)

  Add the 5 phrases above to tests/test_pipeline.py: the first four to
  test_emergencies_are_flagged, the "don't want to die from this" one to
  test_ordinary_concerns_are_not_flagged.

Known limit to say out loud, not fix now
  Past events and other people still fire: "I had chest pain last year",
  "I fainted once 3 years ago", "my mom passed out years ago". Report the false-alarm
  rate on the labelled posts instead of chasing these with more regex.

B1. Dev split has a different label mix from test                  scripts/select_pool.py
------------------------------------------------------------------------------------------
Problem
  Test is a plain random sample. All 544 train/dev posts come from the targeted draw
  (37 per label) plus 100 random ones. τ and the margin are tuned on dev, so they'd be
  calibrated to a label mix the test set doesn't have. pool.ids.csv doesn't record which
  trainval posts were random and which were targeted.

Fix
  1. Add a "draw" column to pool.ids.csv: "random" or "targeted".
     In main(): tag each id in `picked` as targeted and each id from rng.sample(...) as
     random before shuffling.
  2. When splitting trainval into train/dev, take the 50 dev posts from the 100 random
     ones only. The other 50 random + all targeted posts are train.
  Re-run select_pool.py with the same seed before anyone labels (ids won't change; only
  the new column is added).


B2. Record which suggested labels were changed                           tools/annotate.py
------------------------------------------------------------------------------------------
Problem
  Train/dev posts show an AI-suggested first-pass label. Without a record of changes, the
  report can't show the review was real rather than click-through.

Fix
  Add "draft_primary" and "changed_from_draft" to COLUMNS. In save(), store the draft
  label shown (post.get("draft_primary") or "") and
  changed_from_draft = draft != "" and primary != draft.
  Report: "we reviewed N AI-suggested labels and changed X%".
